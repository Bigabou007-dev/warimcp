Every provider, a different integration. Until now.

Collecting mobile money in Côte d'Ivoire, Sénégal or Bénin means juggling provider-specific APIs, webhook formats, retries and reconciliation. WariMCP normalizes all of it behind one clean surface — payments, payouts, refunds, payment links and signature-verified webhooks — with an idempotency-key model that makes double charges structurally impossible.

🔌10 providers, 1 surface

FedaPay, Hub2, CinetPay, Wave, Flutterwave, KKiaPay, Moneroo, MTN MoMo, PAPSS — plus a mock provider so you can build with zero credentials.

🔐BYOK. No custody.

You bring your own provider accounts. Funds settle from your customer directly to your PSP account. WariMCP orchestrates; it never holds money.

🧾Idempotent by design

Every payment and payout carries an idempotency key. Retries, timeouts and duplicate webhooks can't create duplicate charges.

🛰️Runs anywhere

A single Node service with PostgreSQL. Docker-ready. MCP stdio for AI clients, HTTP for everything else — or both at once.

The first agent-payable payment gateway for West Africa

WariMCP speaks MCP natively — Claude, Cursor and any MCP client get typed tools like initiate_payment and initiate_payout. And with x402 enabled, an agent doesn't even need an account: it hits the API, receives a 402 Payment Required challenge, signs a USDC micro-payment on Base, and the call settles automatically. Discoverable in the x402 Bazaar. 

// An AI agent (or you) — no API key, no signup
import { wrapFetchWithPayment } from "@x402/fetch";

const pay = wrapFetchWithPayment(fetch, account);
const res = await pay(HOST + "/api/v1/payments/initiate", {
  method: "POST",
  body: JSON.stringify({
    provider: "fedapay",
    amount: 5000, currency: "XOF",
    idempotencyKey: "order-1234",
    customerName: "Awa Kone",
    customerPhone: "+2250707070707",
  }),
});
